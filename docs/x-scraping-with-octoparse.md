# Octoparse を使った X（旧Twitter）情報収集 自動化手順書

無料のノーコード Web スクレイピングツール **Octoparse** を使って、X（旧 Twitter）の
「自分のタイムライン」と「通知」を定期的に取得し、CSV / Excel / JSON
で書き出すまでの手順をまとめたものです。Qiita 等で紹介されている
Octoparse の一般的なワークフロー（ログイン → ループ → 抽出 → エクスポート）を、
X の DOM 構造に合わせて具体化しています。

---

## 0. 事前に必ず読むこと（重要）

- **X の利用規約**は、API を介さないスクレイピング・自動収集を明示的に禁止しています
  （[X Developer Agreement](https://developer.x.com/en/developer-terms/agreement-and-policy)、
  [Terms of Service](https://x.com/en/tos) 4. "Using the Services" を参照）。
  業務利用や再配布・公開を伴う収集は **X API v2 の有料プラン** を使ってください。
- 本手順は **自分自身のアカウントで、自分が閲覧できる情報を、個人利用の範囲で
  ローカルにアーカイブする** ことを想定しています。第三者の非公開情報や、
  公開情報の大量収集・転売には使わないでください。
- 過度なリクエスト（短時間に何百件もスクロール、複数アカウント並列）は
  bot 検知の対象となり、**アカウント凍結のリスク** があります。
  本手順は「1 日 1〜数回、最新 50〜100 件」程度の頻度を前提にしています。
- Octoparse 内蔵ブラウザでのログインは、X 側からは通常のブラウザログインと
  ほぼ同じに見えますが、ログイン情報は **Octoparse のローカル設定** に保存されます。
  共有 PC では使わないでください。

これらに同意できる場合のみ、以下に進んでください。

---

## 1. Octoparse のインストールとアカウント作成

1. <https://www.octoparse.jp/> から Windows 版（または macOS 版）をダウンロード。
2. インストール後、無料アカウントを作成してログイン。
   - 無料プラン（Free）でローカル実行・10 タスクまで作成可能。
   - 定期実行（クラウドスケジューラ）を使いたい場合は Standard 以上が必要です。
3. メイン画面の「**＋ 新規**」→「**カスタマイズタスク**」を選択。

---

## 2. タスクA：自分のタイムラインを取得する

### 2-1. URL の設定

「URL を入力」欄に以下を貼り付けて **保存** をクリック。

```
https://x.com/home
```

Octoparse の内蔵ブラウザでページが開きます。**初回はログイン画面**が出るので、
以下の手順でログインしてください。

### 2-2. ログインステップを記録する

1. 画面右上の **「ブラウズ」モード（手のひらアイコン）** を ON にする。
2. 内蔵ブラウザ上で **自分の X アカウントにログイン** する
   （ユーザー名 → 次へ → パスワード → ログイン）。
3. ログイン完了後、ホームタイムラインが表示されることを確認。
4. **「ブラウズ」モードを OFF** に戻す。
5. 左側のワークフローパネルで、各ログイン操作（「テキスト入力」「クリック」）が
   ステップとして記録されていることを確認する。
   - これらが「**ログイン → ホーム遷移**」の自動化ステップになります。
6. 「**Cookie を記憶**」オプションを ON にすると、次回以降ログイン操作を
   スキップできます（ワークフロー → URL ステップ → 詳細設定）。

> **Tips:** X は不審なログインに対して 2 要素認証や CAPTCHA を出すことがあります。
> その場合は「ブラウズ」モードで手動対応し、Cookie を保存した状態で運用してください。

### 2-3. 無限スクロールの設定

X のタイムラインは無限スクロール式なので、追加ロードを行うステップを足します。

1. ワークフロー右上の「**＋**」→「**ループ**」を追加。
2. ループタイプを「**ページの下までスクロール**」に設定。
3. スクロール方法：**1 画面分ずつ**、待機時間 **3〜5 秒**、繰り返し回数 **5〜10 回**
   （= 約 50〜100 件のツイートを読み込む目安）。

> 繰り返し回数を大きくしすぎると bot 検知に引っかかります。
> まずは 5 回程度から始めて、安定動作を確認してから増やしてください。

### 2-4. ツイートをループで抽出

1. ブラウザ上でタイムラインの **最初のツイート全体（カード）** をクリック。
   → Octoparse が「これは要素ですか？」と聞いてくる。
2. 「**すべての類似要素を選択**」を選ぶ。
   → 画面上のすべてのツイートカードがハイライトされる。
3. 「**各要素をループでデータ抽出**」を選ぶ。
   → `Loop Item` ステップが自動生成される。
4. ループ内の最初のツイートで、以下の要素を 1 つずつクリックして
   「**このテキストを抽出**」していく：

   | 抽出フィールド | クリックする位置 | フィールド名（例） |
   |---|---|---|
   | 投稿者表示名 | カード上部の名前 | `display_name` |
   | 投稿者ハンドル | `@xxxx` の部分 | `handle` |
   | 投稿時刻 | 「3時間」「May 23」など | `posted_at` |
   | 本文 | ツイート本文 | `text` |
   | 返信数 | 吹き出しアイコンの数字 | `reply_count` |
   | リポスト数 | リポストアイコンの数字 | `repost_count` |
   | いいね数 | ハートアイコンの数字 | `like_count` |
   | 表示数 | グラフアイコンの数字 | `view_count` |
   | ツイート URL | 投稿時刻のリンク → **リンクの URL を抽出** | `tweet_url` |

5. 各フィールドのカラム名をわかりやすい英字に変更（上表の右列を参考に）。

### 2-5. ツイートが「広告」「プロモ」の場合の除外

ループ内に「**条件分岐（IF）**」を追加し、`text` または親要素に
"Promoted" / "プロモーション" を含む場合は **スキップ** するように設定すると、
広告ツイートを除外できます。

## 3. タスクB：通知を取得する

タスクA と同じ要領で、URL だけ差し替えた別タスクを作ります。

```
https://x.com/notifications
```

抽出フィールドの推奨は以下：

| フィールド | 内容 |
|---|---|
| `notification_type` | 「いいねしました」「フォローしました」など |
| `actor_name` | アクションを起こしたユーザー名 |
| `actor_handle` | `@xxxx` |
| `target_text` | 対象となった自分のツイート抜粋（存在する場合） |
| `occurred_at` | 「3時間」など |
| `url` | 通知をクリックした際の遷移先 |

通知ページも無限スクロールなので、2-3 と同じスクロールループを入れてください。

---

## 4. 実行とデータエクスポート

1. 画面右上の「**実行**」→「**ローカルマシンで実行**」をクリック。
   - 無料プランではローカル実行のみ。
2. 実行ログを見ながら、想定どおりに抽出できているかチェック。
3. 完了後、「**エクスポート**」から以下のいずれかを選択：
   - **Excel (.xlsx)**
   - **CSV**
   - **JSON**
   - **データベース**（MySQL / SQL Server / Oracle、有料）
4. 出力先フォルダを指定して保存。

### 推奨：日付ごとにファイル名を分ける

エクスポート時のファイル名テンプレートに `{TaskName}_{yyyy-MM-dd_HHmm}` を
指定しておくと、後でアーカイブとして扱いやすくなります。

---

## 5. 定期実行（スケジューリング）

### 無料プランの場合：Windows タスクスケジューラを使う

1. Octoparse のタスクを右クリック → 「**コマンドラインを生成**」。
2. 生成されたコマンドを Windows の「**タスク スケジューラ**」で
   1 日 1〜数回実行するよう登録。
3. macOS の場合は `launchd` または `cron` で同等のことが可能。

### 有料プランの場合：Cloud 実行

1. タスク編集画面で「**クラウドで実行**」を選択。
2. 「**スケジュール**」タブで頻度（毎日 9:00、6 時間ごと等）を指定。
3. Cookie ベースのログイン状態が切れた場合は再ログインが必要。

> **注意:** あまりに短い間隔（例: 5 分ごと）で実行すると X 側の
> レート制限・bot 検知に確実に引っかかります。**最低でも 1 時間以上** の間隔を推奨。

---

## 6. トラブルシューティング

| 症状 | 原因 / 対処 |
|---|---|
| ログインできない / CAPTCHA が出る | ブラウズモードで手動ログインして Cookie を保存。VPN を使っている場合は OFF に。 |
| ツイートが 0 件 / 少ししか取れない | スクロール待機時間を 3 → 6 秒に延長。読み込みが遅い回線でも安全に。 |
| 「ログインしてください」画面に戻る | Cookie の有効期限切れ。タスクの最初に「ログインステップ」を再記録。 |
| 一部フィールドが空 | X の DOM 変更によくある。該当フィールドを再選択して XPath を更新。 |
| アカウントに警告が出た | 即座に実行頻度を下げ、数日間は手動利用のみに留める。 |
| 文字化け（CSV） | エクスポート時のエンコーディングを **UTF-8 (BOM 付き)** に変更。 |

## 8. 補足：本格運用する場合は API への移行を推奨

ノーコードスクレイピングは **「お試し」「個人の手元アーカイブ」** には向きますが、
以下に該当する場合は **X API v2（Basic 以上）** への移行を強く推奨します。

- 業務として継続的に収集する
- 取得データを社内外で共有・分析する
- アカウント凍結が業務上許容できない
- 大量データ（1 日 1000 件以上）を扱う

API への移行後は、本リポジトリ内に Node/TypeScript のクライアントを
実装してこのドキュメントを差し替えることを想定しています。
